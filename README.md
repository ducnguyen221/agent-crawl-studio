# Agent Crawl Studio

Safe web and media crawling for agents: plan, fetch and extract with a manifest and security policy.

**Incubating build (bản ươm), not a release.** Private, local git only, no remote. SPR-01 delivered the skeleton (pinned engine venv installed by `opcos-runtime ensure`, `capabilities`, a download smoke test), SPR-02 the `plan` and `run` core, SPR-03 media download with yt-dlp, cancellation, retries and `retry`. Replace the sample skill, fill in `LICENSE`, review every file for private data, and only then consider publishing.

## Layout

- `skills/example-skill/SKILL.md` is a minimal sample skill. Rename it, or add skills beside it.
- `.claude-plugin/plugin.json` is the source of the plugin declaration; keep `.claude-plugin/marketplace.json` and `.codex-plugin/plugin.json` consistent with it.
- `tests/test_scaffold.py` checks the structure (manifests, skill front matter, links).
- `AGENTS.md` holds the rules for agents working in this repository; `ECOSYSTEM.md` states its role and hand-offs.

## Commands

- `scripts/crawl-studio.ps1 capabilities` prints one JSON line (engine versions, ffmpeg, node, work root). If the core venv is missing it prints a `DEPENDENCY_MISSING` line with the `ensure` hint and exits 0; it never installs anything.
- `scripts/crawl-studio.ps1 plan --request <file>` (SPR-02, slice A) reads a v1 request (UTF-8 JSON, at most 1 MiB; one leading BOM is accepted, as Windows PowerShell 5.1 writes one) and prints one JSON plan line: per-item `allow`/`blocked` decision with a fixed error code, the output place and the effective limits. It opens no socket, creates nothing, and never opens a request path that starts with two separators (UNC), names a device (`CON`, `NUL`...) or a stream. Exit 0 when the request is valid (blocked items included), 2 when it is refused. With the core venv missing the launcher prints `DEPENDENCY_MISSING` and exits 2 for `plan`/`run` (0 for `capabilities`).
- `scripts/crawl-studio.ps1 run --request <file>` (SPR-02, extended in SPR-03) downloads the URLs of a v1 request, one after another, into a new `<work_root>/jobs/<job_id>/` folder (`files/`, `logs/run.log`, `manifest.json`) and prints ONE JSON line equal to the final `manifest.json` (result v1). Exit 0 succeeded, 1 failed, 2 refused before running (invalid request, output path, space), 3 partial, 130 cancelled. Direct downloads over HTTP(S): a pinned-IP transport checks every address at connect time, redirects are followed and re-checked step by step (max 5, no https to http), any `Content-Encoding` other than identity is refused, sizes and times are limited, files are named `<id>-<10 hex of sha256>.<safe extension>` and are never overwritten. Limits: items run sequentially (`concurrency` is accepted but not applied), `gallery` and `crawl` give `UNSUPPORTED_SOURCE`, no cookies, no login, no robots.txt. Loopback and private addresses are refused; there is no switch for that.
- **Media (SPR-03).** `mode: media` and `mode: auto` download one video or audio file per URL with yt-dlp, only for `https` port 443 URLs whose host is in `media_host_allowlist` (`config.example.json`); in `media` mode any other URL is `URL_BLOCKED`, in `auto` it falls back to the direct download. Each item gets its own local filtering proxy (`127.0.0.1`, random port, per-item token) that accepts only `CONNECT` to a name on port 443, resolves it once and connects only to a public IP, counts bytes against the size cap and logs refusals (redirect to another host: `REDIRECT_BLOCKED`). It is a cooperative control, not a sandbox (ADR-005). The engine's whole process tree runs in a Windows Job Object and is ended when the item finishes, times out or is cancelled. Needs yt-dlp (core venv), ffmpeg and node; if one is missing the item fails with `DEPENDENCY_MISSING`.
- **Cancel.** Ctrl+C ends the whole process tree of the running item (engine, node, ffmpeg), removes its partial files, marks the item `cancelled` and exits 130 with a complete manifest.
- **Retries.** `limits.retries` (default 3, hard cap 5, `0` turns retrying off) tries an item again inside the job, only for a trouble that can pass by itself: `NETWORK_ERROR` marked `retryable`, `RATE_LIMITED` of the direct adapter, and a `TIMEOUT` of the connect or idle wait. Waits are 2, 4, 8, 16, 32 s (the last repeats); a `Retry-After` of at most 120 s replaces the wait, a longer or unreadable one ends the tries. Never retried inside the job: a `TIMEOUT` of the item or the job, `RATE_LIMITED` of yt-dlp, a 403, a blocked URL, a size limit, any other code; no try goes past the job deadline.
- `scripts/crawl-studio.ps1 retry --manifest <manifest.json> --request <file>` runs again, in a new job, the items of an old job that are `failed` with `error.retryable: true` or `cancelled`. The request must be the one the old job ran (same URLs, checked by hash); the manifest must be a finished result inside an allowed job folder. The new manifest carries `retry_of` (the old job id); the old manifest and folder are not changed. Nothing to retry, or a mismatch, is refused with exit 2.
- **Limits.** `limits.media_item_timeout` (default 2700 s, hard cap 4 h) is the time budget of a yt-dlp item; `item_timeout` (default 600 s) stays for direct downloads. Defaults and hard caps of every limit are in `src/agent_crawl_studio/limits.py`.
- **Output place.** The work root is `CRAWL_STUDIO_WORK` (absolute path), else derived from `OPCOS_ROOT` or `USERPROFILE`. The allowed output roots are the work root plus the `output_roots` of `<work_root>/config.json` (an entry may be an absolute path anywhere). A request `output_dir` outside them is refused with `OUTPUT_PATH_BLOCKED` (exit 2); a `retry --manifest` path outside them is refused with `INVALID_REQUEST` (exit 2).
- `python scripts/smoke_download.py --url <url> --work <dir> [--plan-only]` (core venv Python) is a thin layer over the core: it builds a one-URL request (mode `media`), calls `runner.run` (or `runner.plan` with `--plan-only`) and prints one JSON line with `ok`, `BLOCKED_ENV` (a missing tool or a name that does not resolve), `FAIL` or `NOT_RUN`; exit 0 only for `ok`, 130 when interrupted. `--work` is the request's `output_dir` (the core decides the place; a job folder is made under it). URL rules, media host list, DNS probe, engine, folders and cleanup are all the core's; the script keeps no copy.
- **Residual risks (ADR-005).** The proxy cannot stop a child process that chooses to go around it: node (the signature solver) ignores the proxy variables and can open direct connections, so JS from a hostile source could reach an address outside the proxy. The proxy token sits in the engine's command line while the item runs. A short window exists between starting the engine and assigning it to its Job Object. A public IP that really belongs to the local network (hairpin) is not told apart from the internet. OS-level isolation is out of scope.
- Engine and pins: `requirements/core.txt`, `locks/core-windows.txt`, `opcos-runtime.json` (venv `core`, own scope, no `install.package`). Config sample: `config.example.json`.

## Local use

Use the skills from this checkout with an agent that supports skill directories. For Claude-compatible plugin tooling, add the local marketplace `.claude-plugin/marketplace.json` and install `agent-crawl-studio@agent-crawl-studio`. Codex-compatible metadata is in `.codex-plugin/plugin.json`. Installation and routing across harnesses are not validated by the scaffold.

## Verify

Run `python -X utf8 -m pytest tests -q -p no:cacheprovider --cov=src` with the system Python (needs `pytest` and `pytest-cov`; set `PYTHONDONTWRITEBYTECODE=1`). Tests use only the standard library, inject every collaborator, touch no network and create no `.venv` in the checkout.
